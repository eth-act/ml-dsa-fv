# Gas-optimised ML-DSA verifiers (MlDsaOpt)

`MlDsaOpt/{44,65,87}/opt.hex` are EIP-8355 verifiers for ML-DSA-44/65/87
(FIPS 204 `ML-DSA.Verify`, empty context, full SHAKE, compressed public key,
no precomputation, no external contracts). They have the same interface and
semantics as the proved reference (`MlDsa44/Spec.lean` `spec` and the
parametric `MlDsa/Spec/Interface.lean`). All three are generated by one
parametric generator, `scripts/gen_opt.py`.

There are two generator versions:

* **v3** is the current version (round 3), written to `MlDsaOpt/NN/`. It is
  formally verified: `MlDsaOpt44/`, `MlDsaOpt65/` and `MlDsaOpt87/` prove
  these bytes (all four final theorems, standard axioms only). Section
  "Round 3 (v3)" lists the subroutines that differ from v2.
* **v2** was verified first (git tag `opt-v2-proved`). `python3
  scripts/gen_opt.py --version v2` still writes those bytes to
  `MlDsaOpt/NN/v2/`; `scripts/opt_selftest.py` checks they are byte-identical
  to the v2 artifacts (SHA-256 pinned).

## Reproducing

```sh
export TMPDIR=$PWD/.lake/tmp
python3 scripts/gen_opt.py                     # v3: MlDsaOpt/{44,65,87}/{opt.hex,opt.asm,layout.txt}
python3 scripts/gen_opt.py --version v2        # v2 (proved bytes): MlDsaOpt/{44,65,87}/v2/
python3 scripts/opt_diff.py                    # subroutines changed v2 -> v3 (modulo relocation)
scripts/opt_forge.sh MlDsaOpt/44/opt.hex 44    # revm: 48 vectors + 3591 corpus cases, verdicts + gas TSV
scripts/opt_forge.sh MlDsaOpt/65/opt.hex 65    # revm: vectors/mldsa65/calldata.txt
scripts/opt_forge.sh MlDsaOpt/87/opt.hex 87
python3 scripts/opt_fuzz.py 65 400 111         # differential fuzzing (Python EVM vs FIPS model + dilithium-py)
python3 scripts/opt_selftest.py                # model, kernels, constants, all vectors, forced 6th squeeze
python3 scripts/opt_worstcase.py               # worst-case gas over adversarial inputs, per set
.lake/build/bin/mldsa44tool run-file MlDsaOpt/44/opt.hex FILE   # Lean-semantics gas (one calldata per line)
python3 scripts/gen_opt.py --version wc        # wc (data-dependent paths, not proved): MlDsaOpt/{44,65,87}/wc/
python3 scripts/opt_diff.py --from v3 --to wc  # subroutines changed v3 -> wc
python3 scripts/opt_worstcase.py --version wc  # worst case of the wc build
python3 scripts/opt_fuzz.py --version v3,wc 44 400 341   # same cases on several builds, accepted mean per build
python3 scripts/opt_corpus.py 44 v3,wc         # Python EVM: corpus verdicts, gas median / mean / max per build
```

`scripts/opt_evm.py` is a Python Osaka interpreter with exact frame gas. It
reproduces the reference's 12,953,021 and agrees with revm on every case
above. `profile=True` gives per-pc gas, and the generator's regions turn that
into per-subroutine gas.

## Round 3 (v3)

Round 3 kept the design, the interface and the exact FIPS semantics. To keep
proof churn low it changes only a few subroutines.

* **Changed subroutines.** `scripts/opt_diff.py` compares each subroutine's
  instruction sequence modulo relocation: jump targets are compared as
  (subroutine, offset). This is the notion of "byte-identical" that
  `scripts/proofgen_port.py` ports. Every subroutine not listed below is
  byte-identical to v2.
* **v2 stays reproducible.** Every v3 change is gated on `Layout.v3` in the
  generator, so `--version v2` still produces the proved bytes.

| step | gas 44 / 65 / 87 | changed subroutines | memory contracts |
|---|---|---|---|
| R3-1 (65 only) | − / −188,542 / − | `expand_a` (the group driver in the main region); new `pass3x5` … `pass3x8` | unchanged: same ABUF / ACC / ZH regions. The schedule assigns 65's row-group-1 instances to arbitrary slots |
| R3-2 | −22,807 / −22,711 / −35,943 | `kf1`; `main` (only the top-of-memory constant, +800 B) | `kf1` now also clobbers the new region KZ (800 B, appended at the end of memory, so no other address moves). Memory size: 44 2065 → 2097 words, 65 2833 → 2865, 87 2865 → 2897 |
| R3-3 | −8,704 / −17,408 / −17,408 | `usehint` | unchanged (same inputs ACC / HP / SP, same output) |

The full v2 → v3 lists:

| set | changed | added | unchanged |
|---|---|---|---|
| 44 | `main` (one immediate), `kf1`, `usehint` | – | the other 25 |
| 65 | `main` (one immediate), `expand_a`, `kf1`, `usehint` | `pass3x5`, `pass3x6`, `pass3x7`, `pass3x8` | the other 22 |
| 87 | `main` (one immediate), `kf1`, `usehint` | – | the other 24 |

Re-proof scope:

* `main`: only the PUSH3 that touches the top of memory changed, so the
  memory size changes. `memWords` changes for every subroutine's proof;
  `proofgen_port.py` already substitutes it.
* `kf1`: the new 3-round body. The decay lemma becomes:
  * windows after 3 rounds with offset −1, `decay_windows(3, -1)`, asserted
    in `opt_keccak.py`; all lanes are valid on [189, 256), which contains
    [192, 256);
  * re-replication = (w >> 192) · REP;
  * buffers KS → KB → KZ → KS.
* `usehint`: two lemmas.
  * the exact quotient D = ((r + g2 − 1) · M) >> K for (K, M) = (38, 2886403)
    when 2γ2 = 190464, and (42, 16793617) when 2γ2 = 523776;
  * ((D >> 1) + m − h + 2(h & D)) mod m = UseHint(h, r).

  Both are checked exhaustively over r < q in `opt_selftest.py`.
* 65 `expand_a` and `pass3x*`: groups 5–8 have new slot roles, and each
  `pass3x` adds, per coefficient word, one or two masked and lane-shifted
  products, ACC_1[t] += ((ABUF[t] & mask) << / >> 64d) · ẑ_j[t]. Products
  are < 2^51; sums over 5 columns are < 2^54, the same bound as v2's
  row-group-1 accumulation.

### What each step does

* **R3-1, 65 schedule.** v2 ran rows 4 and 5 in 5 groups with 2 idle slots
  each. The 10 instances now share 4 groups with tr (3 runs), H(c̃) and μ:

  | group | slots |
  |---|---|
  | 5 | A(4,0), A(5,0), A(4,1), tr₀ |
  | 6 | A(5,1), A(4,2), A(5,2), tr₁ |
  | 7 | A(4,3), A(5,3), A(4,4), tr₂ |
  | 8 | A(5,4), c̃, μ, – |

  This removes 5 kf4 and 5 `blk` calls. The 45 kf4 calls are the minimum for
  65 with 5-squeeze instances.
* **44 and 87 schedules are already minimal.**
  * 44: each instance needs 5 consecutive squeezes in one slot, and tr needs
    10 sequential ones. In 24 calls, 3 slots hold 4 instances each and the tr
    slot holds 2, so at most 14 of the 16 instances fit. 25 calls are needed.
  * 87: 75 calls give 300 slot-permutations, and all 300 are used (280
    ExpandA, 20 tr).
* **R3-2, kf1.**
  * With the shift offset −1, every rotation is a left shift. A search over
    per-round offsets (`decay_windows`) found that the window after 3 rounds
    is [189, 256): the top 64-bit copy stays valid.
  * Re-replication is therefore needed only every 3 rounds and needs no mask
    (4 ops instead of 6).
  * A 3-round body cannot alternate between two buffers, so a third buffer KZ
    is used.
  * Cost: 32,586 gas per call (v2: 35,895).
* **R3-3, UseHint.** Since 2γ2 · m = q − 1, D = ⌊(r + γ2 − 1)/γ2⌋ = 2·r1 + [r0 > 0]
  (with the r = q − 1 corner case folded into mod m). One exact
  multiply-shift replaces the r1 quotient and the 13-op sign test. This
  saves 11 ops per word (usehint 64,793 → 56,089 per row group).

## Design

Every subroutine is listed with its pc range in `MlDsaOpt/NN/layout.txt`.

### Keccak-f[1600] (`scripts/opt_keccak.py`)

A single round template, emitted with explicit stack scheduling and two
rounds per loop iteration, generates both variants:

* **kf4** packs four Keccak states per word, bit-interleaved: bit b of slot k
  sits at bit 4b + k. Bitwise operations act on all four states at once, and
  a 64-bit rotation of every state is one 256-bit rotation by 4n
  (DUP, SHL, SWAP, SHR, OR). It costs **40,238 gas** per call, i.e. ~10.1k per
  state permutation.
* **kf1** holds one state with each lane replicated as x‖x‖x‖x.
  * Rotations are single shifts by d = n or n − 64 ("decaying window").
  * Bitwise operations intersect the valid bit windows.
  * Two rounds from full windows leave every lane valid on bits [58, 200)
    (`decay_windows()` asserts this), so the second round of each iteration
    re-replicates bits [64, 128) before storing.
  * It costs **35,880 gas** per call.

Both variants share the following:

* **Lane complementing.** Lanes 1, 2, 8, 12, 17 and 20 are stored inverted,
  so chi needs about 1 NOT per plane. The callers initialise those lanes to
  all-ones and invert them on output.
* **Operand consumption in chi.** B4, B1, B0, B3, B2 are pushed in that
  order, so outputs 2, 3 and 4 consume their operands in place: 10 DUPs and
  no POPs per plane.
* **Hand-scheduled theta.** Each C is copied once and consumed once
  (5 DUP + 6 SWAP).
* **Iota** comes from a 24-word table (interleaved, or replicated).

### SHAKE and ExpandA

* **SIMD groups.** A schedule (`build_schedule`, printed in `layout.txt`)
  assigns the four slots of each kf4 "group" (5 squeezes) to roles:
  * ExpandA instances A[r][j];
  * a 5-block run of tr = H(pk), continued in the same slot by the next
    group;
  * SampleInBall's H(c̃);
  * unused.

  The layouts per set:

  | set | ExpandA layout | where tr runs (5 blocks per group) | H(c̃) |
  |---|---|---|---|
  | 44 | groups = (column j, rows 0..3) | slot 3 of the last 2 groups | extra group |
  | 87 | groups = (column j, rows 0..3) | slot 3 of the last 4 groups | kf1 |
  | 65 | groups = (column j, rows 0..3) | row group 1's idle slots (rows 6, 7 do not exist), free | row group 1 |

  For 44 and 87, the A instances that tr displaces go to one extra group.
* **Single sponges.** The final c̃ hash uses kf1.
  * μ: for |M| ≤ 69 (one padded block), μ is absorbed into a free slot
    (`mu0`): 44's extra group, or 65's row group 1 after tr. It is squeezed
    by that group's first permutation.
  * Otherwise, and always for 87, μ is a kf1 sponge seeded from tr's lanes
    extracted from the SIMD slot.
* **Absorption.** Calldata words are byte-swapped per 64-bit lane and either
  multiplied by 1 + 2^64 + 2^128 + 2^192 (kf1), or spread to stride 4 with
  6 masked shift-OR stages and XORed into one slot (`trabs`, kf4). Squeezed
  lanes are read directly, or compressed out of a slot (`cext`).
* **Per squeezed kf4 block (`blk`).**
  1. The 21 rate words are de-interleaved with 6 delta swaps: bit 4b + k
     goes to 64k + b.
  2. The block's 56 positional RejNTTPoly candidates of all four slots are
     written as row-packed words (lane = slot), one word per coefficient
     index.
  3. One rejection-flag word is recorded per 8 candidates.
* **Fix-up (`fix`).** A slot with a rejection among its first 256 candidates
  (P ≈ 22% per instance) is compacted in place:
  * Groups of 8 without a rejection become 8 masked word copies.
  * Flagged groups are branch-free: every candidate is written at wp, and wp
    advances by 32·[v < q]. A rejected value is overwritten by the next
    accepted one; writes never overtake rp.
  * A sixth squeeze is made on demand, saving and restoring the kf4 state,
    because slots may carry tr. The 1008-byte bound is exact.
* **Fused accumulation.** ACC_rb[t] += ABUF[t] · ẑ_j[t] adds 4 rows per word
  with one lane-wise MUL. The extra group uses a Kronecker product: the
  displaced instances sit in slots 3, 2, …, ẑ is shifted into lanes 0, 1, …,
  and lane 3 of the product is the dot product.

### Polynomial arithmetic

* **Lane-packed polynomials.** A word holds four different polynomials at
  the same coefficient index in 64-bit lanes: z grouped by polynomial, ACC by
  row. Every NTT butterfly is therefore one word operation with a scalar
  zeta (`scripts/opt_ntt.py`).
* **NTT and inverse NTT** use Montgomery multiplication per lane (R = 2^32).
  * Layers are merged 3 + 3 + 2, with 8 words on the stack.
  * The docstring gives the bound argument for every layer.
  * 256^-1 and the Montgomery factor are folded into the last inverse layer.
  * The inverse NTT also Montgomery-reduces the accumulator words as it
    loads them in its first pass, so there is no separate reduction pass.
  * Cost: 99,705 per forward NTT and 119,593 per inverse NTT (including the
    reduction), each covering 4 polynomials.
* **c·t1 is computed sparsely in the normal domain** (`tbuild`, `csum`). This
  removes NTT(t1), NTT(c) and the t1 decoding.
  * Each row group has a 6 KB table of 16-bit fields interleaved by row:
    1023 − t1, then t1, then 1023 − t1.
  * One unaligned 32-byte MLOAD reads 4 coefficients × 4 rows, so the
    product costs 64·τ loads per 4 rows.
  * The 1023 bias per negative term becomes −1 mod q after the factor 2^13
    (2^13 · 1023 = q − 1), so it is corrected by the running count n_neg(t)
    of negative contributions. SampleInBall keeps the nonzero list directly.
* **z decoding** works on 4 polynomials at once:
  * byte-reverse the calldata word;
  * gather 3 coefficients per 64-bit lane;
  * apply SIMD norm checks: ((raw + C2) << 32) | (K − raw + C1) is
    OR-accumulated, and bits zbits + 32 and 25 must stay clear.
* **UseHint** runs on 4 rows per word with an exact multiply-shift quotient
  for x mod q and for (r + γ2 − 1) / 2γ2 (constants checked exhaustively).
  Its output is packed directly into the 64-bit lanes the final hash absorbs.
* **Hint decoding** follows Algorithm 21 exactly and writes row-packed hint
  bits.

## Provenance: Yul or bytecode

**Every component was written as hand-written bytecode**, generated by
Python with a readable intermediate form:

* **Generators:**
  * `scripts/opt_asm.py`: assembler with a named-stack tracker; it asserts
    stack layouts at loop back-edges;
  * `scripts/opt_keccak.py`: Keccak rounds;
  * `scripts/opt_ntt.py`: NTT kernels;
  * `scripts/gen_opt.py`: everything else and the main flow.
* **Intermediate form:** `MlDsaOpt/NN/opt.asm`, an annotated listing with
  pc, mnemonic, immediate and subroutine.
* **Structure:** `MlDsaOpt/NN/layout.txt` gives the subroutine pc ranges, the
  memory map and the SIMD schedule.
* **Functional model:** `scripts/opt_ref.py` holds a Python FIPS 204 model
  with intermediate values. It agrees with all 161 vectors and served as the
  oracle for every kernel.

**No `opt.yul` is provided.** The compiler is the bottleneck for every hot
kernel:

* They hold 8–16 live values on the stack (Keccak rows, NTT butterflies over
  8 words, de-interleave masks). The verified compiler without its optimizer
  spills or rejects that; Yul has no stack-depth control and no way to emit
  hand-scheduled sequences (the consumption orders in chi and theta).
* The reference Yul's `keccakF` (54k gas) is 35–50% more expensive than kf4
  or kf1, and its NTT (210k per polynomial) is 8x the 4-lane kernel per
  polynomial.

A Yul back-port would only serve as documentation. The Python model and the
listing serve that role here, so no Yul was written for any component. As
with the reference, the proofs target the bytes; compiler provenance was
documentation only there too.

## Opcodes

The opcodes used are ADD, SUB, MUL, MOD (87 only), LT, GT, EQ, ISZERO, AND,
OR, XOR, NOT, SHL, SHR, PUSH0–32, DUP, SWAP, POP, CALLDATALOAD, CALLDATASIZE,
MLOAD, MSTORE, MSTORE8, MCOPY, JUMP, JUMPI, JUMPDEST and RETURN.

**All of them are in the stepper's set** (`EvmProof/Stepper.lean`
`runInstr`). The following are not used: ADDMOD, MULMOD, DIV, BYTE,
CALLDATACOPY, STOP, CODECOPY, SAR, EXP and SIGNEXTEND.

* MCOPY occurs only on the sixth-squeeze path, to save and restore the kf4
  state.
* MOD occurs only in 87's kf1 SampleInBall (p mod 136).

A CODECOPY zeta table (saves ~1.7 KB of code for the NTT records) and a
MULMOD rotation (14 instead of 21 gas) were considered and rejected:

* MULMOD by 2^256 − 1 is wrong when the word is all-ones, which cannot be
  ruled out for attacker-influenced states.
* CODECOPY is outside the supported set.

## Floor analysis: why 1M is out of reach

The 44 verification needs the following Keccak-f[1600] permutations for an
empty message. Only μ and the final hash are inherently sequential.

| item | permutations |
|---|---:|
| ExpandA: 16 SHAKE128 instances × ≥ 5 squeezes (≥ 768 bytes each) | 80 |
| tr = H(pk): 1312 bytes | 10 |
| H(c̃): ≥ 1 block | 1 |
| μ | 1 |
| final H(μ ‖ w1Encode): 832 bytes | 7 |
| **total** | **99** |

* **Keccak lower bound per permutation, this approach.** Per round, the
  ≥ 106 bitwise operations of theta, chi and iota (with lane complementing),
  29 rotations, and ≥ 50 memory accesses come to at least ~380 opcodes for a
  4-way interleaved state (6-opcode rotations) and at least ~260 for a
  replicated single state (2-opcode decaying rotations). At 3 gas each that
  is **≥ 27k per kf4 call and ≥ 19k per kf1 call**. Ours are 40.2k and 35.9k.
  The difference is mostly stack traffic (DUP/SWAP) and loading lanes twice
  per round.

  Round 2 re-costed this with the state kept in memory, which is
  unavoidable since 25 lanes do not fit a 16-deep stack. Every term is
  already near its own minimum: kf4 at 1,677 gas per round = rotations 609
  (29 × 21; the 14-gas MULMOD rotation is unsound on all-ones words) + lane
  loads/stores ~450 + D application 150 + column parities 210 + chi 465 (10
  DUPs per plane is minimal when each B is used 3 times). Computing the next
  round's column parities inside chi was ruled out: DUP/XOR/SWAP/POP per
  output cost more than the 8.4 gas per reloaded lane they save. So the
  practical floor of this design is about 38k (kf4) and 34k (kf1), not
  27k / 19k.
* **Keccak floor.** With perfect 4-way packing, 91 parallelisable
  permutations need ≥ 23 kf4 calls, plus 8 sequential kf1:
  23 × 27k + 8 × 19k ≈ **0.77M**. Ours is 25 kf4 + 7 kf1 = 1.26M.
* **Packing overhead.** De-interleaving the 20 squeezed 4-state blocks of
  ExpandA is 420 words × 6 delta swaps ≈ 0.09M.
* **Arithmetic floor:**
  * 2 four-lane NTTs at ≥ 15 opcodes per butterfly: ≈ 0.1M;
  * A·ẑ: 1024 lane-wise products with memory traffic: ≈ 0.05M;
  * sparse c·t1: ≥ 64·τ loads ≈ 0.04M;
  * z decode, norm check, UseHint and packing: ≈ 0.1M.
* **Total floor ≈ 1.15M** for this design family: compressed key, FIPS
  SHAKE, opcode-level Keccak, no helper contract. Ours, at 2.14M, is 1.86x
  that.

Reaching 1M would require removing work, not implementing it better:

1. **An expanded public key** (Â and t̂1 as calldata or code, as ZKNox and
   Fireblocks do).
   * It removes 90 of the 99 permutations, `blk`, `fix` and `trabs`: about
     1.4M of the current 2.14M.
   * With the kernels here the rest would be about 0.8M: 9 kf1 calls, the
     NTTs, and A·ẑ read from the key.
2. **A Keccak-f precompile or opcode**, which would remove ~70% of the cost.
3. **A cheaper permutation in the EVM cost model.** No known technique gets
   a Keccak-f round under ~1k gas.

## Proof plan sketch

The bytecode is a set of subroutines with fixed memory contracts. The
reference's infrastructure applies: `evm_reach` block tactics,
located-instruction certificates from the generated listing, and call and
loop composition. The likely contracts, bottom up:

1. **kf4 / kf1** (`KS` → Keccak-f).
   * Precondition: KS holds an interleaved state (resp. a replicated state)
     in complemented form; RC tables are initialised.
   * Postcondition: same form of Keccak-f(state) per slot. Constant gas.
   * Proof: symbolic execution of the generated 2-round body, plus lemmas
     that the interleaved 256-bit rotation is a per-slot 64-bit rotation and
     the lane-complementing chi identities (`CHI` table).
   * For kf1, the decaying-window invariant: bit-window intersection lemmas
     and `decay_windows` as a checked computation.
2. **blk.** Bit-permutation lemmas: delta swaps compose to unzip, with
   bit 4b + k ↦ 64k + b. Candidate extraction gives 3 bytes per lane with
   bit 23 masked. The flag word is OR of (a + 2^23 − q).
3. **fix, gfix.** Loop invariant: lane s of ABUF[0, wp) equals the first
   (wp − ABUF)/32 accepted candidates of the slot's stream, and rp is the
   next unread candidate. Flag-clean groups preserve the invariant with a
   shift. Equivalence to the bounded `rejNTTPolyOf` (1008-byte bound, sixth
   squeeze) follows the reference's sampling-scan lemmas. The state backup
   makes the sixth squeeze side-effect free.
4. **ginit, trabs, cext, schedule.** Per-slot sponge semantics: spread and
   compress are bit permutations. Kept slots carry the tr state across
   groups. Fresh slots absorb ρ‖j‖i or c̃ with padding.
5. **ntt / intt.** Per-lane FIPS Algorithms 41/42, using the layer-bound
   argument in the `opt_ntt.py` docstring (lanes < 2^27.2 forward, < 2^35
   inverse, Montgomery inputs < 2^58) and the Montgomery reduction lemma
   (low 32 bits of t + mq are zero).
6. **pass3, pass3m, pass3k.** Lane-wise product lemma (products < 2^51,
   sums < 2^57, no cross-lane carry). The Kronecker identity: lane 3 of
   X·Z′ = Σ_i X_{3−i} Z′_i, and lower lanes stay below 2^64.
7. **intt load reduction, usehint, pack.** Exactness of the multiply-shift quotients:
   K = 53 for x mod q on x < 2^32, and the 2γ2 dividers. The UseHint formula
   (r1 + m + h(2·pos − 1)) mod m equals Algorithm 40 (checked exhaustively
   here; a symbolic proof needs a range split). w1 bit-stream packing.
8. **tbuild, csum.** The windowed-sum identity: 2^13·S′(t) + n_neg(t) ≡
   2^13·(c·t1)(t) (mod q), with S′ < 2^16 per field. The SampleInBall list
   invariants (BASES/IDX/CW).
9. **dz, decode_hint, sample_in_ball, hash_mu, final_hash.** These mirror
   the reference contracts. The z norm check is the SIMD range lemma.
10. **main.** Composition and the gas schedule.

The gas schedule must charge the worst cases measured in "Worst-case gas"
(next section).

## Worst-case gas

`scripts/opt_worstcase.py` reports, for each set, the maximum over
adversarial inputs at a given calldata length. Control flow depends on data
in only four places:

1. RejNTTPoly fix-ups and the sixth squeeze;
2. SampleInBall's byte loop;
3. HintBitUnpack's loops;
4. μ's block count, which depends on the message length only.

The script measures each routine in isolation (crafted memory, `start_pc`)
on its most expensive path:

* **Fix-ups:** all 42 flag words set, 256 accepted plus 80 rejected
  candidates, and one sixth squeeze per group.

  per-instance worst case from 45,193 to 32,279.
* **The worst case is not reachable in practice.** It needs a rejection in
  every ExpandA instance (≈ 0.22^n) together with a sixth squeeze
  (≈ 10^-38 per instance). Accepted fuzz cases peak at 2.45M (44), 4.26M (65)
  and 5.78M (87).
* **All worst cases fit the 16.6M budget.** For longer messages add one kf1
  call (~36k) plus absorption per 136 bytes of μ input.
