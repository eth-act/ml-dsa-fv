# ML-DSA-44 verifier in EVM bytecode, formally verified

A Lean 4 proof that a frozen EVM bytecode computes FIPS 204
`ML-DSA.Verify` for ML-DSA-44 behind the
[EIP-8355](https://eips.ethereum.org/EIPS/eip-8355) interface, with a proved
gas bound. Proof style and generic infrastructure follow
[powdr-labs/eip8200-challenges](https://github.com/powdr-labs/eip8200-challenges).

## Statement

`MlDsa44/Spec.lean` is the whole audit surface on top of the pinned EVM
semantics:

* calldata = `pk (1312 bytes) ‖ σ (2420 bytes) ‖ M`, empty context string;
* the bytecode returns one word, `1` iff `ML-DSA.Verify(pk, M, σ, "")`
  accepts, `0` otherwise (including calldata shorter than 3732 bytes);
* `Correct code`: from a fresh Osaka frame, every sufficiently large gas
  budget evaluates to that return;
* `CorrectWithSchedule code schedule`: `schedule |calldata|` gas suffices.

`MlDsa44/Spec/Fips202.lean` defines SHAKE128/256 on top of the semantics'
Keccak-f[1600]; `MlDsa44/Spec/Fips204.lean` transcribes FIPS 204 Algorithms
3, 8 and their subroutines. The only permitted deviation used is the bounded
XOF output of FIPS 204 Appendix C (RejNTTPoly ≤ 1008 bytes, SampleInBall ≤ 272
bytes, both above the Table 3 minimums); hitting a bound rejects.

The spec is executable and checked against the NIST ACVP ML-DSA-44 sigVer
vectors and generated vectors including malformed hints and norm boundaries:

```sh
export TMPDIR=$PWD/.lake/tmp
lake build mldsa44tool && .lake/build/bin/mldsa44tool spec
```

## Implementation

`MlDsa44/Reference/reference.yul` (generated by `scripts/gen_reference.py`)
is compiled by the pinned verified Yul compiler without its optimizer, so
every Yul function is one bytecode subroutine:

```sh
.lake/build/bin/mldsa44tool compile MlDsa44/Reference/reference.yul MlDsa44/Reference/reference.hex
.lake/build/bin/mldsa44tool run MlDsa44/Reference/reference.hex   # vectors + gas
```

5289 bytes; about 12.95M gas for a 0-byte message, +85k per 136 message
bytes. The theorems are about the frozen bytes
(`MlDsa44.referenceBytecode`); compiler provenance is documentation only.

## Proof structure

| Module | Content |
|---|---|
| `EvmProof/` | Generic direct-bytecode infrastructure, vendored from eip8200-challenges |
| `MlDsa44/Proofs/Artifact.lean` | Generated instruction list, assembly equation, located instructions |
| `MlDsa44/Proofs/Layout.lean` | Memory map, representation predicates, the `Call` contract form |
| `MlDsa44/Proofs/Fn/*.lean` | One contract per subroutine (pre/postcondition over memory, frame, gas budget) |
| `MlDsa44/Proofs/Bridge.lean` | Pure lemmas aligning the spec with the implementation's data flow |
| `MlDsa44/Proofs/Gas.lean` | The public schedule, composed from subroutine budgets |
| `MlDsa44/Proofs/Main.lean` | Whole-program traces and `reference_correctWithSchedule`, `reference_correct` |

`lake build MlDsa44` checks everything; `#print axioms
MlDsa44.Proofs.reference_correct` lists any remaining `sorry`.
